# v6：写穿透一级数据缓存

目标是降低重复数据读取对外部内存的访问，建立可验证的数据缓存基线。继承 v5 的 F/X/W 单发射流水线、
RV64IMAC/特权/Sv39、半字缓冲、256B I-cache 与取指提前重启；v1–v5 独立冻结。
所有版本优化动机与演进关系见 [根 README](../../README.md)。

## 结构与选择依据

```text
F/X requests -> arbiter -> MMU -> D-cache -> I-cache -> atomic adapter -> external RAM / MMIO
                           |        |          |
                    permissions   data       instructions
                    + PTW bypass  256B       256B
```

这是一条共享物理事务通路，两块缓存按请求类别处理各自的流量；不是双端口外部总线。
MMU 新增 d_cache_data，只在最终普通数据访问时为真，页表读取为假。每次命中之前仍检查虚拟地址与权限。
I-cache 的背景补数仍可能阻塞 D-cache 向外发请求。

| 项目 | 本版实现与原因 |
|---|---|
| 容量/映射 | 256B，16行×16B，直接映射；便于观察命中和同索引冲突 |
| 地址 | 物理 tag=PA[15:8]，index=PA[7:4]，offset=PA[3:0] |
| 读命中 | 寄存响应，提取原地址开始的1/2/4/8字节，LSU再完成符号扩展 |
| 读缺失 | 两笔8B读取，完整成功后分配并返回；本版D-cache没有提前重启 |
| 写命中 | 写穿透，等待外部成功响应后按字节更新已有缓存行 |
| 写缺失 | 直接写内存，不分配、不驱逐同索引的其他tag |
| 事务 | 阻塞式，每次一笔上游请求，外部最多一笔在途，无写缓冲 |

写穿透让已经完成的普通存储及时对内存可见，便于页表、原子操作和自修改代码的验证。
代价是每笔存储仍访问外部，不能获得写回缓存的写合并收益。寄存器数组尚未映射为 SRAM 宏。

## 旁路、错误与一致性边界

- 只缓存平台普通RAM物理地址0x0000–0xffef中不跨行的最终普通数据读取。
  0xfff0–0xffff整行不缓存，包含退出邮箱；高地址MMIO和高物理别名也不缓存。
- 指令读取、页表读取、所有LR/SC/AMO原子操作旁路，原子元数据和bus_lock保持原协议。
  原子请求被接受时使对应数据缓存行失效，后续普通load重新读取，避免AMO/SC后的旧副本。
- 写命中响应失败会使该行失效；读缺失任一补数失败都报错，绝不把部分行置为有效。
  单元测试注入首笔/第二笔读取错误及写错误；整核测试检查异常语义。
- reservation_invalidate 还会清空全部D-cache有效位，毒化在途补数/写更新。
  这是单核环境提供的外部变更通知入口，未实现多核一致性协议或自动DMA侦听。
- FENCE无需冲刷脏行，因为没有脏行/异步写缓冲；既有串行化规则确保先前访存完成。
  FENCE.I继续使I-cache及取指缓冲失效，普通代码存储已通过写穿透到达内存。
- 物理缓存命中不能绕过新特权/新页权限检查。PTW旁路确保PTE读取看到已经写穿透的页表更新。

RTL模块为 `rtl/rv64_dcache.sv`。hit/miss/refill/write/bypass事件由仿真宿主在沿前计数，
不会为了观测增加64位RTL反馈计数器。data_wait沿用X处于DATA_RSP且尚无响应的周期计数，
不包含DATA_REQ尚未被接受的等待，也不是所有访存停顿之和。DCACHE_ENABLE=0关闭数据缓存，保留其他机制；
同轮30个测试的周期数和外部请求数均与v5完全一致。

## 实测性能与代价

[本轮60组主对照](../../results/comparisons/20261101T101150839524Z/comparison.csv)
使用相同二进制，逐条提交与最终64KiB RAM均经过独立模型检查。
[D-cache的30组开关对照](results/20261101T101150839524Z/dcache-ablation.csv)记录等待与请求数，
其他开关实验也保存在同轮目录，旧实验没有覆盖。

| 程序 | 延迟1/间隔0：v5→v6 | 延迟5/间隔3：v5→v6 | 外部请求：v5→v6 |
|---|---:|---:|---:|
| 重复读取同一数据128次 | 1564→1567 | 2127→1627 | 136→10 |
| 顺序求和 | 927→1054 | 1371→1499 | 74→74 |
| 指针追踪 | 1055→1310 | 1631→2135 | 138→138 |
| 裸机C | 492→527 | 1043→1059 | 101→94 |
| 压缩指令依赖链 | 245→245 | 431→431 | 36→36 |

重复读的128次load有127次命中、1次缺失；高延迟有背压时data_wait从538降到39，
总周期减少约23.5%，外部请求减少约92.6%。低延迟时命中响应与理想内存一样快，
第一次完整补行额外增加3周期，所以不会更快。

顺序求和每两个8字节load占一行：一次缺失需要两次外部读，下一次命中省一次读，
总外部读取数基本抵消；等待完整行和内部状态转换却增加周期。指针程序也表现出这种退步。
这说明仅有命中率不足以判断性能，下一阶段应重点研究D-cache关键数据提前返回或更细补数策略。
本版如实保留这个可比较的完整补行基线。

Nangate45 typical、相同约束、理想时钟下，布局前最小周期估计4.32→4.54ns，
标准单元面积103466.286→125400.646，增加约21.2%。因此即使指令类程序总周期不变，
估计执行时间也会随时钟周期变长。开关关闭配置没有独立测量时序，不套用默认配置周期来估算其时间。

```sh
# 仓库根目录默认v6
make lint test

make diagrams
make compare BENCHMARK_ARGS="--versions v5_early_restart v6_dcache"

```

558项D-cache单元检查覆盖各读取宽度/字节偏移、所有存储宽度和字节保留、
直接映射冲突、写不分配、旁路与原子别名失效、读写错误、补数中失效以及内存/响应背压。

暖数据行后的U权限拒绝与物理别名、缓存过的PTE写穿透及页表更新。
原有整数、M/A/C、CSR、中断、Sv39、FENCE.I、取指跨页及流水线测试全部保留。
261组扩展/特权/流水线/缓存整核测试在RTL与门级分别通过，522份提交/最终内存文件逐字节一致。
门级采用标准单元逻辑模型，不含SDF延迟。
