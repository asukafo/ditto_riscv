# v9：静态分支预测与直接跳转目标预测

目标是减少v8循环分支的冲刷。v8在F按顺序取指，等X算出真实跳转后再重定向。
[初始基线](results/20261101T111040503285Z/baseline-v8.json)记录：延迟5/间隔3的求和执行64条条件分支，
发生63次冲刷、63次取指响应丢弃，共1111周期；基线提交与最终RAM也通过独立模型验证。

继承v8的F/X/W单发射流水线、独立I/D MMU与缓存命中路径。v1–v8分别冻结，
整体演进思路见[根README](../../README.md)，访存结构见[v8设计](../v8_split_memory/README.md)。

## 预测规则与位置

| 指令 | 预测 |
|---|---|
| 向后条件分支，合法funct3且立即数为负 | 跳转到PC+B立即数 |
| 向前或零偏移条件分支 | 顺序PC+指令长度 |
| JAL | 跳转到PC+J立即数 |
| JALR | 顺序取指，等待X解析寄存器目标 |
| 其他指令、非法压缩指令 | 顺序PC+指令长度 |

这是BTFNT（Backward Taken, Forward Not Taken），没有BTB、历史表或返回地址栈。
`rtl/rv64_static_predictor.sv`只依赖当前完整指令、PC与指令长度，不在F读寄存器或计算分支真实条件。
预测发生在取指响应完成/压缩指令解压后，不能在尚未获得指令字节时提前预测。
RV64C的C.J/C.BEQZ/C.BNEZ经解压后使用同一规则；C.JR/C.JALR仍属于间接跳转。
RV64I配置中不预测到非4字节对齐目标，真实执行时仍由原异常逻辑判断是否合法。

## 每条指令携带自己的预测

```text
assembled/decompressed instruction + PC + bytes
                     |
                static predictor
                     |
       F packet: instruction, PC, predicted_next
                     |
       X packet: instruction, PC, ex_predicted_next
                     |
       actual next PC == ex_predicted_next ? continue : redirect + flush
```

`rtl/rv64_fetch.sv`把预测结果同时写入下一取指PC与F输出字段predicted_next。
`rtl/rv64_core.sv`在发射时把该字段保存为ex_predicted_next；X完成时与真实ex_next比较。
不能只检查“真实下一PC是否等于顺序PC”，否则会漏掉“预测跳转、实际不跳”的循环退出。
也不能拿正在向前推进的F端PC代替X所属指令的预测。

预测正确时保留已取到/正在取的目标指令；失误时按真实PC冲刷，排空并丢弃旧请求。
即使预测正确，缓存缺失和响应延迟仍可能产生气泡，不保证每周期发射一条。

压缩指令或半字对齐32位指令预测跳转时，丢弃顺序方向尚未消费的高半字；
拼接中的32位指令要先拿齐后半部分，才能计算目标。输出暂停时预测字段和其他指令字段一起保持稳定。
JAL链接值仍是自身PC+真实指令长度，由原前递/写回路径送给后续消费者，不能用预测目标作为链接值。

## 恢复、异常与错误路径

X仍顺序解析分支，后续指令只有在旧X允许完成且未重定向时才能发射。
预测错误的store、CSR、原子指令不能越过分支产生架构副作用；错误路径的取指异常只保存在F，
失误恢复时一起清除，不提交为异常。推测取指仍可能占用总线和填充缓存。
实际执行的跳转目标缺页则正常陷入，异常PC为目标地址；跳转自身若不满足对齐等规则仍按原异常语义处理。
FENCE.I、异常、返回和CSR串行化的重定向继续清空取指缓冲；静态预测器没有跨地址空间的历史状态。

`PREDICT_ENABLE=0`恢复顺序取指。保持其他配置不变时，本轮30组周期数和外部请求数与v8完全一致。

## 实测收益与限制

[本轮60组主对照](../../results/comparisons/20261101T111040503285Z/comparison.csv)使用相同二进制，
每条提交与最终64KiB RAM通过独立模型核对。
[30组预测开关对照](results/20261101T111040503285Z/prediction-ablation.csv)保存解析、失误、冲刷和等待；
其他缓存与访存路径开关实验也分别保留。旧版本没有预测观测接口时CSV留空。

| 程序 | 延迟1/间隔0：v8→v9周期 | 延迟5/间隔3：v8→v9周期 |
|---|---:|---:|
| 求和 | 923→798 | 1111→983 |
| 寄存器依赖链 | 665→541 | 715→591 |
| 指针追踪 | 1051→926 | 1871→1623 |
| 重复读同一数据 | 1437→1185 | 1491→1239 |
| 裸机C | 451→440 | 963→955 |
| M/A/C C | 470→472 | 843→843 |
| 短访存程序 | 99→96 | 195→199 |
| 独立ALU | 742→742 | 1623→1623 |

求和64条条件分支只失误1次，即循环退出；按下一PC准确率为63/64，约98.44%。
冲刷63→1、前端等待168→36；外部请求仍为73，收益来自减少冲刷和前端交接等待，不是缓存容量增加。
并非所有程序改善：短访存程序在延迟5/间隔3时195→199，M/A/C C在低延迟时470→472；
更少冲刷仍可能改变取指/数据请求竞争时机。直线程序没有分支，周期数不变。
裸机C有12条间接跳转，M/A/C C有8条，它们本轮全部失误，说明返回/间接目标预测仍是后续候选。

同Nangate45 typical约束下，布局前最小周期估计4.83→4.64ns，单元面积129741.500→131956.748，增加约1.71%。
求和高延迟时间模型5366.13→4561.12ns，改善约15.0%。映射后的周期变化不等于预测准确率导致的频率变化；
RTL路径与门级映射都发生了变化。关闭开关的配置没有单独测量时序，不套用默认周期估算其时间。
这些是布局前估计，不是实际芯片频率或硬件实测时间。

## 观测指标

control_resolved在X有效完成时计数，分成conditional_branches/direct_jumps/indirect_jumps；
control_misses是该指令真实下一PC与保存预测不同的次数，同样按三类细分。
predicted_redirects统计预测下一PC不同于顺序PC的已解析控制流，PREDICT_ENABLE=0时为零。
统计由宿主在沿前采样，不新增RTL64位反馈计数器。解析事件以X为准，退出尾部可能有已解析但尚未提交的指令。

这里衡量的是下一PC是否正确：例如目标恰好等于顺序PC时，两种方向不会造成地址失误。
flush_count还包括CSR/FENCE/异常/返回等重定向，不能当作纯分支失误数。
