# v48 双 hart 共享内存原型

顶层 `rv64_dual_hart` 实例化两个从 v47 派生的顺序双发射核。两核从 PC 0 启动，通过只读 CSR `mhartid` 得到 0 和 1。每个核有独立的 PC、寄存器堆、特权状态、预测器、I/D TLB 和私有 I-cache。原型的代码区在运行期间保持只读。

```text
hart 0 ── req / rsp ──┐
                       ├── 轮询仲裁 / 响应归属 / 原子锁 ── 共享 RAM
hart 1 ── req / rsp ──┘                   │
                         写入成功后向另一个 hart 报告写地址
```

## 内存与原子操作

共享数据访问关闭每核 D-cache，普通 load/store 经同一共享物理总线访问 RAM。仲裁器在竞争时轮询选择，请求遇到背压时保留选择。总线最多保留一笔在途请求，记录接收请求的 hart，并把响应交还给它。

原子适配器把 AMO 拆成读和写。仲裁器在收到带 `bus_lock` 的请求后保留其所有权，覆盖读写之间的空隙。SC 的权限探测同样受锁保护。实际写入成功响应后，另一 hart 的原子适配器检查写入地址与本地保留区是否重叠。这个原型用对齐的 8 字节粒度跟踪保留区，所有请求均为自然对齐且最多 8 字节。权限探测和失败写入不会触发失效。 [RISC-V A 扩展规范](https://docs.riscv.org/reference/isa/unpriv/a-st-ext.html)

## 仿真

在仓库根目录运行 `make test-multicore`。Verilator 用同一份裸机程序启动两核，两个 hart 各执行 64 次 `amoadd.d`，共享计数器应得到 128。仿真宿主在看到 hart 0 退休 LR 后放行 hart 1，用软件 store 验证两种情况。写入与保留区重叠的字节使 SC 失败，写到保留区外时 SC 成功。仿真还检查背压期间请求稳定、AMO 中间无其他请求插入和两核在同一周期退休指令。

| RAM 响应延迟 / 请求间隔 | 用例周期数 | 两核同时退休的周期 | 共享 RAM 请求 | 请求背压周期 |
|---|---:|---:|---:|---:|
| 1 / 0 | 660 | 10 | 328 | 0 |
| 5 / 3 | 2574 | 4 | 322 | 640 |
| 11 / 7 | 5790 | 3 | 322 | 1924 |

周期数包含共享计数器竞争和测试同步，反映该用例在不同内存条件下的行为。本轮验证范围是裸机共享 RAM，带一致性的私有 D-cache、核间中断控制器、共享 L2、多笔内存事务和 Linux SMP 启动属于后续阶段。仓库默认命令使用 v47 单核入口，v48 可用 `VERSION=v48_dual_hart` 选择单核回归入口，双 hart 仿真使用专用目标。
