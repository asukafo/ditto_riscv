# v4：复用取指数据的半字缓冲

沿用 v3 的三级 F / X / W 单发射流水线、256 字节物理指令缓存和完整的特权/MMU功能。
本版改动集中在 F 内部：保存一次 32 位读取中尚未消费的高半字，减少重复取指与缓存查询。
本版现已独立冻结；当前开发和默认构建入口选择 v5。

## 缓冲里保存什么

```text
+----------------------- 32-bit read ----------------------+
|       upper 16 bits        |       lower 16 bits          |
+----------------------------+-----------------------------+
              |                            |
        saved halfword                  decode now
        + virtual PC                       |
        + valid                            v
              +-----------------> complete instruction -> X
```

新增 spare_valid、spare_half 和 spare_pc，一个有效位、16 位数据和对应虚拟地址。
原来的完整指令输出缓冲仍保留。它们都属于 F，不增加流水线级数，也不改变每周期最多发射一条指令的规则。

- 低半字是压缩指令：解码低半字，保存高半字，下一条先检查缓冲。
- 保存的半字也是压缩指令：直接解码，可以在上一条进入 X 的同一沿替换 F 输出，无需新的缓存查询。
- 保存的是普通指令的低半字：保存前缀，再请求后半部分，拼成完整 32 位指令。
- 后半部分从下一个对齐字读取，未使用的高半字继续保存，可处理连续的半字对齐普通指令。
- 没有匹配缓冲时按 v3 的请求规则读取；缓冲地址必须与 next_pc 相同。

缓冲项只记录一次已成功读取、已经过 MMU 权限检查的数据。对齐的 32 位读取不会跨页。
跨页普通指令的后半部分仍要单独请求和翻译，不能拿低半字的权限代替下一页权限。

## 重定向与暂停

分支、异常、返回、CSR/FENCE 等串行化提交产生重定向时，完整指令输出、半字缓冲和拼接前缀一起清除。
旧请求若已经被接受，则继续接收响应并丢弃，不把旧响应重新写回缓冲。
因此即使返回的目标虚拟地址与旧缓冲地址相同，也必须重新检查新特权/翻译上下文。
FENCE.I 仍按 v3 的规则使 I-cache 失效，同时清除新的半字缓冲。

输出 valid 且下游不 ready 时，所有指令字段保持不变。只有输出为空或本沿被接收时，才能将保存的半字转换为新输出。
这一规则允许连续交接，也避免 X 因访存或乘除暂停时覆盖尚未发射的指令。

## 可观察指标与独立开关

仿真宿主在上升沿之前采样 fetch_buffer_reuse_event 和 fetch_buffer_flush_event，
输出 fetch_buffer_reuses 与 fetch_buffer_flushes。统计不增加新的 RTL 64 位计数器。
复用次数按半字消费计数，既包含完整压缩指令，也包含普通指令的低半字，不能直接当成完成指令数。
统计截止到退出存储提交沿，包含错误路径和未提交的取指；末尾也可能仍有尚未完成的请求。

FETCH_BUFFER_ENABLE=0 的构建保留同一核心和 I-cache，恢复 v3 的取指行为；
ICACHE_ENABLE=0 的构建则保留缓冲，仅关闭缓存。两个控制可以分离不同改动的收益。
公共比较器会检查 v4 关闭缓冲时的周期数和外部请求数与同一轮 v3 完全一致。

## 验证与复现

```sh
# 在本版本目录执行以下命令（根目录使用 VERSION=v4_fetch_buffer）
make lint test
make test-fetch
make test-mapped
make diagrams
make compare BENCHMARK_ARGS="--versions v3_icache v4_fetch_buffer"
# 仍可单独使用冻结的旧版本
make test VERSION=v3_icache
```

前端单元测试检查连续压缩指令、跨字/跨行普通指令拼接、跨页故障归属、响应到达时重定向、
已有半字时重定向、内存背压和输出暂停。集成测试另外检查：

- 普通/压缩指令混合执行与半字对齐的连续普通指令。
- 从已保存低半字进入下一虚拟页，分别验证非连续物理映射和缺页。
- 代码更新后 FENCE.I，确保压缩指令与缓冲中的旧半字不再使用。
- 半字对齐的 MRET 后，目标地址即使与预取数据相同，仍重新检查 U 权限。
- 缓冲中的非法压缩指令正确陷入，错误路径不能产生存储副作用。

以及 [27 组关闭缓冲对照](results/20261031T110922495130Z/fetch-buffer-ablation.csv) 独立保存。
低延迟压缩基准由 v3 的 345 降到 279 周期，缓存查询由 137 降至 69；外部请求仍为 36 次。
含 M/A/C 的 C 程序由 538 降至 500 周期；主要由 32 位指令构成的程序周期数保持不变。

布局前最小周期估计由 4.30 变为 4.32 ns，单元面积由 101875.606 变为 103070.212，增加约 1.17%。
改善集中于压缩和混合指令流，不能宣称所有程序都更快；冷行补齐仍有成本，低延迟压缩基准仍略高于 v2 的 277 周期。
缓存大小、补齐策略和分支处理均未改变；本版没有 D-cache、TLB、分支预测、乱序或多核。
