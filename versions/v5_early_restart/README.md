# v5：关键字优先与提前重启

在 v4 的 F/X/W 单发射流水线、半字缓冲和 256 字节物理指令缓存上，优化冷缺失的等待。
本版现已冻结；默认开发入口为v6。v1–v4 也分别冻结。缓存仍为 16 行，每行 16 字节，使用两次 8 字节物理读取补齐；容量和接口不变。

## 为什么这样做

v4 必须等整行的两次读取都结束，才返回本次所需的 2/4 字节。
v5 先读包含请求字节的 8 字节；如果请求全部落在该半行，成功后立即登记响应。
前端获得指令后可以发射、执行、提交，I-cache 同时继续读取剩余的半行。
请求若跨越 8 字节边界，则保留等完整行后返回的路径；跨行请求仍直接旁路。

```text
v4: [read low 8B] [read high 8B] -> instruction -> execute
v5: [read critical 8B] -> instruction -> execute
                      [read remainder 8B] -> complete valid cache line
```

“关键字优先”决定两次读取的顺序；“提前重启”允许第一笔数据先供执行。
这不是增加流水线级数或发射宽度，也不是非阻塞缓存。剩余补数期间不接收新的上游请求，
不会同时存在两笔外部请求，数据访问也可能等待背景补数完成。

## 控制与错误处理

`rtl/rv64_icache.sv` 的 `early` 记录本次请求能否提前返回；`beat` 表示第一/第二笔读取。
`fill_high` 由原地址 bit 3 与 beat 决定，高半行也可以先读。
`fill_low` 保存第一次回来的 64 位（名字沿用旧版，它现在也可能是高半行），最后按物理偏移组装整行。
`response_available` 独立保存响应是否尚未被接收，因此响应握手和背景补数可以各自推进。

- 响应 valid 而 ready 为 0 时，数据与错误位保持不变，即使背景读取已经完成。
- 第一笔关键数据失败：返回访问错误，不分配有效缓存行。
- 第二笔失败且关键数据已经成功返回：不为无关字节追补一个异常，缓存行保持无效；后续访问重新读取。
- 非提前返回路径中的任一读取失败：整个本次请求报错。
- FENCE.I 继续清除 valid，并毒化在途补数；旧补数可以排空，但不能重新置 valid。
- MMU 仍在缓存之前检查权限。PTE、数据、原子与 MMIO 继续旁路，物理可缓存范围仍为 64 KiB RAM。

`EARLY_RESTART=0` 恢复 v4 的补齐与响应行为，其他前端机制保留。
本轮 27 组关闭优化的周期数和外部请求数，逐项与同轮 v4 一致。

## 实际波形

[冷行补齐波形](docs/waveforms/icache-cold.svg) 与 CSV 来自真实 Verilator VCD，latency=5、gap=3。
控制信号采沿之前，commit 信号采沿之后：

| 周期 | 事件 |
|---|---|
| C5 | 外部接受地址 0 的第一笔 8 字节读取 |
| C10 | 第一笔数据返回 |
| C11 | p_rsp_valid/ready 握手，把关键字送回 MMU/取指；另一笔读取正在等待 |
| C12 | 第一条指令发射到 X |
| C13 | 外部接受地址 8 的剩余读取 |
| C14 | PC=0 的指令提交，此时缓存仍在补数 |
| C18 | 第二笔数据返回，整行随后变为有效 |

这里 `rsp_valid` 是外部内存返回；`p_rsp_valid` 是 I-cache 向 MMU 返回。
两者属于不同接口，提前响应不会伪造第二次内存返回。

```sh
# 在本版本目录执行；根目录选择 VERSION=v5_early_restart

make test-mapped
make diagrams
make compare BENCHMARK_ARGS="--versions v4_fetch_buffer v5_early_restart"
```

新增 103 项缓存定向检查覆盖低/高半行优先、重排序后的所有半字、关键/非关键错误、
跨半行回退、背景补数时失效，以及长期响应背压。原有缓存单测以关闭优化运行，保留旧行为验证。

标准单元映射后再次运行全部 221 组扩展/特权/流水线/缓存/缓冲测试，逐条提交与最终内存均经独立模型检查。
442 份逐条提交/最终内存文件在 RTL 与门级运行间逐字节一致。门级仿真使用逻辑模型，不含 SDF 延迟。
