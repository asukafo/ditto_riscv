# v2：单发射顺序流水线

本版从 v1 演进，现作为冻结的流水线基线；当前开发见 [v3 指令缓存版](../v3_icache/README.md)。源码和构建产物均独立。保留 RV64IMAC、Zicsr/Zifencei、M/S/U、精确异常、
中断、Sv39/Svade 和现有仿真总线约定。没有缓存、乱序执行或多核。

## 为什么这样分阶段

```text
F：取指与指令缓冲 → X：操作数寄存、执行/访存等待 → W：顺序提交
       ↑                       │                        │
       └──── 分支、异常重定向 ──┘                        │
                               ←── X/W 结果前递 ────────┘

F 请求 ─┐
        ├─ 数据优先仲裁 ─ MMU ─ 原子适配器 ─ 单个主存接口
X 请求 ─┘
```

F 使用独立 PC，缓冲一条完整指令，并能在消费缓冲的同周期发起下一次取指。
压缩指令读一次半字，普通指令读两个半字，跨页部分分别经过 MMU。
X 保存自己的 PC、指令与操作数，执行 ALU/分支，或等待访存/迭代乘除完成。
W 保存完成结果并统一产生 commit、写通用寄存器、更新 CSR/退休计数，或进入异常。

这样划分的依据是寄存器边界与现有接口：先分离独立取指和体系结构状态更新，
在保留可验证顺序语义的同时实现阶段重叠。它不是经典五级，也没有把状态名称换一下就当作流水线。
F、X、W 各有独立的有效状态；X 完成进入 W 时可以同时接收下一条指令。
程序里的多条指令能同时处在不同阶段，每周期最多发射一条、提交一条。
单端口阻塞内存限制了供指速度，因此不承诺每周期都能发射或提交。

## 关键规则

1. 操作数在发射时寄存。先用本周期完成的 X 结果，再用正在提交的 W 结果，最后用寄存器堆读值。
   x0 永远为零。Load/MUL/DIV 未完成时 X 不释放，较年轻指令留在 F 缓冲中。
2. 分支默认顺序取指。在 X 得到不同目标后清空 F；已经接收的错误路径取指必须排空，响应直接丢弃。
   取指错误与指令一起排队，只有到达 W 才产生异常，错误路径故障不会提前陷入。
3. CSR、返回、WFI、SFENCE 和 FENCE 类指令串行化。先让较老指令提交，阻止新取指，
   排空已接收的事务，再在 W 更新控制状态并重取后续指令。CSR 的 rdtime/minstret 在实际提交时读取。
4. 中断先阻止新发射/取指，等待 X、W 和总线排空，使用已提交的下一 PC 进入处理程序。
   同步异常也在 W 处理，故障指令不提交，较年轻指令不能产生寄存器或数据存储副作用。
5. 取指和数据请求共享一个阻塞接口，数据优先。仲裁器锁住已接受请求的所有字段直到响应，
   重定向不能撤回受背压的外部请求。AMO/LRSC 和页表遍历继续使用原模块。

没有为了追求周期数把 MMU、异常或中断功能删掉。保守串行化有实际代价，后续应由测量决定是否细化。

## 使用与结果保留

```sh
cd versions/v2_single_issue
make lint test
make test-mapped
make timing
make diff PROGRAM=full_demo
make diagrams
surfer build/pipeline.vcd
```

`make test` 保留原指令/扩展/特权验证，增加 25 次流水线专用运行，覆盖前递、x0、错误路径存储、
被丢弃的越界取指故障、精确异常、CSR 顺序与修改代码后的 FENCE.I。
`make test-mapped` 在标准单元功能网表上再执行扩展、特权和流水线测试，不含 SDF 延迟。

`make diagrams` 从真实 VCD 导出 [阶段采样图](docs/waveforms/pipeline.svg) 和对应 CSV。
控制信号取上升沿之前的值，commit 与计数器取沿之后的值，不能把它们错当成同一采样时刻。
图中 C75 将 MUL 的完成结果前递给下一条 ADD，并发射 ADD；C76 同时有 X 中的 ADD 和 W 中的 MUL，
该沿提交 MUL；C77 提交 ADD。这是实际 VCD 中的阶段重叠，不是手工设想的执行顺序。

统计输出增加 overlap_cycles（至少两个阶段持有有效指令/在途取指）、xw_overlap_cycles（X 与 W 同时有效）、
issue_count、bypass_count（发射时选用前递的指令数）和 flush_count。
主机在退出存储提交后停止，所以此时仍可能有较年轻指令在途，issue_count 不要求等于 instret。
涉及 time/中断的测试会因执行速度不同而执行不同次数的等待循环，应比较架构结果与各自参考模型。

构建输出位于本目录 `build/`；永久测试和性能记录放在 `results/<run-id>/`。
从仓库根目录执行 `python3 tools/benchmark.py` 会生成新的时间戳目录，不覆盖历史记录。
时序与面积是同一研究用库下的布局前估计，不能直接作为实际硬件指标。
