# v49 双核与两级缓存

v49 在 [v48 双 hart 原型](../v48_dual_hart/README.md) 上启用每核私有 L1D，并在共享仲裁器后加上 L2。两个核从 PC 0 启动，通过 `mhartid` 选择程序分支。

```text
hart 0 ── L1I / L1D ──┐
                      ├── 轮询仲裁 ── 共享 L2 ── RAM
hart 1 ── L1I / L1D ──┘        │
                  成功写入后按物理地址通知另一核
```

| 层级 | 组织 | 策略 |
|---|---|---|
| 私有 L1I | 每核 256 B、16 B 行 | 裸机用例的代码区保持只读 |
| 私有 L1D | 每核 256 B、16 B 行、直接映射 | 读缺失分配，写穿透，写缺失不分配 |
| 共享 L2 | 4 KiB、128 组、2 路、16 B 行 | 每行两个独立有效的 8 B 扇区，按组记录最近使用的路 |
| RAM | 64 KiB 裸机仿真地址空间 | 一个共享端口，末尾 16 B 保留给邮箱等非缓存访问 |

## 请求和一致性

- L1D 未命中时，经共享仲裁器逐拍向 L2 取数。L2 命中时返回选中的字节。未命中时把原始请求直送 RAM，并在响应握手时安装成功读回的对齐 8 B 扇区。窄读缺失保持原访问宽度。
- 普通 store 穿透 L1D 和 L2。写成功后，L2 丢弃受影响的扇区，写者在本地更新命中行，另一 hart 按物理地址使匹配 L1D 行失效。若该行正在补齐，仍可接收尾拍，但不会重新安装可能混合新旧数据的行。
- AMO 和 LR/SC 绕过缓存查找，读改写及 SC 权限探测到写入的间隙由仲裁锁覆盖。实际写成功后仍走相同的失效路径，另一核的 LR 保留区也按物理地址检查。
- 当前是非包含式缓存层级。L2 替换无需让 L1 的干净副本失效。普通共享数据使用写穿透和按地址失效；当前平台没有 DMA。跨核修改代码涉及额外的指令取值同步，本轮只验证只读代码。 [RISC-V Zifencei 规范](https://docs.riscv.org/reference/isa/unpriv/zifencei.html)

## 仿真和结果

```sh
make test-multicore
make compare-caches
make test VERSION=v49_cache_hierarchy
```

三个配置都启用私有 L1I，执行同一份裸机程序。两个 hart 各执行 64 次 AMO，共享计数器最终为 128。两核先读入同一份旧数据，再由 hart 1 分别写入字节和双字，hart 0 必须读回两个更新后的值。用例还验证 LR/SC 的重叠失效、非重叠写入和背压稳定性。单元测试覆盖 L1D 补行与失效的竞态，以及 L2 的两路、两扇区、错误响应和背压。

下表为 `总周期 / RAM 请求数`。延迟和间隔单位为周期。

| RAM 延迟 / 请求间隔 | 仅 L1I | 私有 L1I/L1D | 私有 L1I/L1D + 共享 L2 |
|---|---:|---:|---:|
| 1 / 0 | 868 / 406 | 842 / 402 | 842 / 345 |
| 5 / 3 | 3122 / 389 | 3192 / 399 | 2810 / 340 |
| 11 / 7 | 6997 / 389 | 7194 / 400 | 6263 / 344 |

相对仅私有 L1，在 5 / 3 的内存条件下，共享 L2 命中 58 次，RAM 请求减少 59 次，完成周期减少约 12%。低延迟下请求减少但周期持平。轮询次数随时序变化，所以表中差异包含轮询和补行的影响。

v49 是裸机仿真原型，外部总线仍为单笔在途。结果是 Verilator 周期数，尚未测量 v49 物理频率或验证 Linux SMP。根目录默认单核入口仍用 v47，多核目标使用 v49。
