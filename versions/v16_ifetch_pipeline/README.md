# v16：I-cache/TLB命中通路连续交接

本版保留v15，独立改变指令侧吞吐。I-cache可以在旧响应被接收的同周期接收新请求；I-MMU允许旧响应与新请求交接，并在合法4KiB ITLB命中时直接送出物理访问。权限、canonical地址与A/D检查仍然存在，miss/大页/页表错误继续使用原walker；数据侧保持原结构。

F对完整、对齐的32位指令，在响应周期可发出预测后继请求；压缩、高半字拼接与不满足条件的路径回退原状态机。新响应必须等待F输出可用，不能覆盖受背压的包。串行、异常和中断准备接管时提前冲刷年轻取指并排空，避免队列占满与提交等待总线互相锁住。

`I_PIPELINE=0`恢复v15。命中通路可以逐周期交接，但本版逻辑接口仍最多一笔在途取指；这不是多笔外部内存事务。更早的取指可能改变RAS使用率，性能对照保留结果，不再把旧版固定命中率当架构要求。

验证：`make -C versions/v16_ifetch_pipeline lint test test-ifetch`。单独的流水取指测试检查背压、半字拼接、重定向与故障。所有提交和RAM继续由独立参考模型核对。

周期对照统一使用`python3 tools/ifetch_experiments.py`，最终与v15及v17运行相同19个二进制；不进行STA或门级仿真。

下一版[v17](../v17_fetch_window/README.md)增加请求槽位和旧响应标记，以实现多笔在途的逻辑取指。旧版说明见[v15](../v15_fetch_queue/README.md)。

实际命中交接审计在直线ALU程序中记录200次“旧响应与下一请求同周期接收”，在途峰值仍为1。`scripts/pipeline_audit.py`可重现该检查。

统一实验`20261102T020843568164Z`：延迟5/间隔3，直线ALU1623→1359周期，分页循环1059→735，C程序887→847。关闭I_PIPELINE的57组周期/请求/控制失误与v15一致。全套596次整核回归、55,947条提交和84项流水前端检查通过。逐条参考校验、源码哈希与审计见[验证记录](results/20261102T020843568164Z/validation.json)，主对照见[CSV](../../results/comparisons/20261102T020843568164Z/comparison.csv)。
