# 第一次时序优化：先确认延迟来自哪里

> v1 多周期基线与早期实验文档。本文中的相对路径和命令均以 `versions/v1_multicycle/` 为工作目录；当前开发版本见 [文档导航](../README.md)。

本轮保持 RTL、状态机、提交周期和 CSR 行为不变。实际修改的是标准单元映射流程：
给 ABC 提供边界驱动/负载约束，使其默认流程增加 buffer、upsize、dnsize。
这改变了门级电路的缓冲结构与单元驱动能力。没有修改目标时钟、放宽路径约束或增加时序例外。

## 设计思路如何得到

先沿最差路径看每一级延迟，再结合扇出、负载电容与转换时间区分问题。
路径终点是 instret，并不能证明计数器是主要瓶颈。

原报告中，指令寄存器 insn[20] 的 Q 直接驱动 1286 个输入端，等效负载约 2173.42 fF，
clk→Q 为 5.2775 ns；之后的寄存器堆读选择又用了 3.8732 ns 和 1.6718 ns。
控制链上三个高负载门另用了约 2.2657、1.6118、3.1030 ns。
这些位置比许多普通组合门几十 ps 的延迟大得多，提示优先检查驱动而非增加流水级。
这类大负载数字也可能涉及 Liberty 查表范围外推，不能当成物理实现的准确值。

原来的 `abc -liberty ...` 默认脚本没有执行 buffer/upsize/dnsize。
安装版 `yosys -p 'help abc'` 明确给出：传入 `-constr` 后才在默认脚本中加入这些步骤。
因此先做一个保持 RTL 不变的受控实验，观察驱动优化本身能解释多少延迟。

```text
原来：一个小驱动直接连接大量门输入

现在：源寄存器 → 缓冲树 → 各组门输入
                          ↑
                  按负载选择驱动尺寸
```

缓冲器不存储数据，也不增加时钟周期。它们在同一个周期内传播相同逻辑值，
以额外面积换取较小的单级负载。新增门本身有延迟，但分担负载后的总延迟可以更小。
这属于基于电路负载与时序报告的工程推导，未照搬某个处理器的架构。

## 本机实际对比

相同 RTL、Nangate45 typical、10 ns 时钟，输入/输出约束均不变：

| 指标 | 原始映射 | 加入缓冲/尺寸优化 |
|---|---:|---:|
| 最小时钟周期估计 | 19.64 ns | 4.32 ns |
| 10 ns 下最差 setup slack | -9.6427 ns | +5.6830 ns |
| 标准单元总面积（库面积单位） | 61253.948 | 65643.746 |
| insn[20] Q 直接扇出 | 1286 | 11 |
| insn[20] Q 等效负载 | 2173.4248 fF | 24.1535 fF |
| insn[20] clk→Q | 5.2775 ns | 0.1363 ns |

面积增加约 7.17%。指令执行周期数不变。
当前关键路径转移到乘除单元，从 remainder[0] 到 result[63]，数据到达约 4.2768 ns，
建立时间约 0.0402 ns，最小周期约 4.3170 ns。
额外尝试的扁平化加缓冲版本为约 4.33 ns，因此这轮保留模块层次。

最小周期的倒数约 231.64 MHz，仅是当前布线前模型的结果；没有布线寄生、实际时钟树和多角签核。
当前低输出负载也是探索性假设，真实接口确定后必须重新约束。

## 验证与复现

```sh
# 原始映射，结果写入 build/timing.log 和 build/mapping.log
make timing ABC_OPTIONS=
# 先保存报告，再跑优化版本
make timing
# RTL lint、基础回归
make lint test-base
# 重新映射，编译门级模型并运行扩展/特权回归
make test-mapped
```

`test-mapped` 用 Yosys 从同一份 Liberty 导出组合逻辑与触发器功能模型，
配合映射网表使用原仿真宿主执行程序，逐条与独立 Python 模型核对提交、异常和最终内存。
它验证门级功能，不包含 SDF 延迟，不能替代 STA，也不等于形式等价证明。
测试覆盖 M/A/C、CSR、异常返回、IRQ、Sv39 与跨页取指，并包含延迟/背压配置。

本轮 `make lint test-base`、`make test-mapped` 与 `make test-full` 全部通过。
门级扩展测试 40 次、特权测试 86 次，共核对 12162 次提交和 118 次软件处理异常/中断事件，
并通过 7 个参考检查器变异测试。
保存门级输出后重新执行 RTL 回归，126 份 trace 和 126 份 RAM 快照的 SHA-256 全部一致；
trace 包含周期字段和最终统计，说明这组测试中的提交时刻、总周期数与功能结果均保持一致。

标准单元库的驱动单元名不是通用名称，换库需同时覆盖 LIB 和 ABC_OPTIONS；
ABC 输出负载使用 fF，OpenSTA 的 set_load 则使用所读库的电容单位。
本项目默认 Nangate45 为 fF，两处均采用 0.01 fF。

参考：[Yosys 官方手册中的 ABC 命令](https://yosyshq.readthedocs.io/_/downloads/yosys/en/latest/pdf/)。
