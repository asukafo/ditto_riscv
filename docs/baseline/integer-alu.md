# 第一批整数指令扩展：位运算、移位与比较

> v1 多周期基线与早期实验文档。本文中的相对路径和命令均以 `versions/v1_multicycle/` 为工作目录；当前默认 v2 见 [文档导航](../README.md)。

本页说明保留在 test-base 中的第一批 ALU 实验。默认配置现已支持 M/A/C、CSR 与 Sv39，见 [模块化实现](modular-core.md)。

本节记录第一批在 ADD、SUB、ADDI 基础上增加的 16 条指令，共 19 条普通 64 位整数计算指令。
仍然使用原有多周期顺序状态机；这些操作在组合逻辑中计算，并在 EXEC 的上升沿写回和提交。
没有增加流水级、指令并发或新的等待周期。RV64I 兼容配置包含 W 运算，见 [RV64I 说明](rv64i.md)。
该兼容配置不启用 B/M；默认配置的 M 使用独立迭代单元。

## 支持的指令

| 功能 | 两个寄存器作为输入 | 寄存器与立即数作为输入 |
|---|---|---|
| 加法 | ADD | ADDI |
| 减法 | SUB | 无独立 SUBI |
| 按位与 | AND | ANDI |
| 按位或 | OR | ORI |
| 按位异或 | XOR | XORI |
| 逻辑左移 | SLL | SLLI |
| 逻辑右移 | SRL | SRLI |
| 算术右移 | SRA | SRAI |
| 有符号小于比较 | SLT | SLTI |
| 无符号小于比较 | SLTU | SLTIU |

比较指令将 0 或 1 写到 rd，不修改分支控制流；这与已有 BLT/BLTU 等分支指令不同。
立即数算术和逻辑指令使用符号扩展的 12 位立即数。特别是 SLTIU：先符号扩展立即数，
再把两个 64 位操作数按无符号数比较，不能直接与 Python 的负数比较。

## 直接运行并观察

```bash
make diff PROGRAM=bit_ops
make wave PROGRAM=bit_ops
make test-alu
```

`bit_ops` 的核心操作如下。初始 t0=-8，其 64 位位模式为 `0xfffffffffffffff8`。

```asm
srli t1, t0, 1     # 高位补 0 → 0x7ffffffffffffffc
srai t2, t0, 1     # 高位复制符号位 → 0xfffffffffffffffc，也就是 -4
slt  t3, t0, zero  # 有符号 -8 < 0 → 1
sltu t4, t0, zero  # 无符号 0xfffffffffffffff8 < 0 → 0
andi t5, t0, 15    # 只保留低 4 位 → 8
xori t6, t5, -1    # -1 符号扩展成 64 个 1，翻转全部位 → 0xfffffffffffffff7
```

同一组寄存器位模式可以按有符号或无符号解释，具体由指令选择。
硬件没有单独的“负数寄存器类型”。算术右移要求保留符号；逻辑右移则只按位移动并补零。

随后程序验证两个容易写错的 RV64 规则：

```asm
addi a0, zero, 1
slli a0, a0, 63    # 0x8000000000000000
addi a1, zero, 64
srl  a2, a0, a1    # 移位量只取 a1[5:0]，64 的低六位为 0，a2 保持原值
```

RV64 的立即数移位量为六位，可以移 0–63 位；不能沿用 RV32 的五位限制。
寄存器移位量也只看低六位，所以 64 等价于移 0 位，65 等价于移 1 位。
对立即数移位编码，解码时检查的是高六位 `insn[31:26]`；`insn[25]` 是合法移位量的一部分。
寄存器操作则检查完整 funct7，只有 SUB/SRA 允许相应的 `0x20`，其他本阶段寄存器运算要求 funct7=0。

程序将 8 个观测值存入 RAM，方便同时从 trace 和内存检查：

| 地址 | 内容 | 数值 |
|---|---|---|
| 0x200 | SRLI 结果 | 0x7ffffffffffffffc |
| 0x208 | SRAI 结果 | 0xfffffffffffffffc |
| 0x210 | SLT 结果 | 1 |
| 0x218 | SLTU 结果 | 0 |
| 0x220 | ANDI 结果 | 8 |
| 0x228 | XORI 结果 | 0xfffffffffffffff7 |
| 0x230 | SLLI 63 结果 | 0x8000000000000000 |
| 0x238 | SRL 寄存器移位量 64 的结果 | 0x8000000000000000 |

当前邮箱退出版提交 22 条指令、有 9 次 SD；LATENCY=1/5/20、GAP=0 时分别为 84/208/673 周期。

## 验证不只靠 RTL 与参考模型相互一致

参考模型同步增加了这 16 条指令。但参考模型也是本项目代码，仍可能与 RTL 同时犯错。
因此 `scripts/alu_tests.py` 还维护一套独立数学期望值计算：

- 移位用乘/除 2 的幂计算；有符号右移使用向负无穷取整的整数除法。
- 用真实汇编器编码输入程序，结果写入 RAM，再与向量期望值比较。
- 对关键语义另外保留直接写出的常量断言，防止数学计算本身误解规则。

共 876 组向量覆盖全部 19 条计算指令：

- 0、全 1、最大有符号正数、最小有符号负数、交错位模式。
- 移位量 0、1、31、32、63，寄存器移位量 64、65、127、128 和全 1。
- 立即数 -2048、-1、0、1、63、2047，以及固定种子 20261031 的随机输入。
- rd=x0 丢弃写回，rd=rs1/rs2、rs1=rs2、x0 源操作数。
- 低 64 位截断、有符号与无符号比较，以及负立即数符号扩展。

每组向量以五种 `(LATENCY,GAP)` 配置运行：`(1,0), (1,3), (5,0), (5,7), (20,3)`。
当前邮箱退出版五次向量程序共核对 26305 条提交，同时独立检查每个操作的写回字段和最终内存输出。
输入表、数学期望值和汇编程序位于 build/alu_vectors.*，输出表位于 RAM 0xc000 起。

基础回归还检查非法 SLLI/SRLI/SRAI 高位、错误 funct7、未支持的 MUL 和保留的 W 移位编码，
要求停止并报告 fault=1，不能产生错误的成功提交。
这些向量和伪随机用例有明确边界，但仍不是完整 ISA 合规验证或形式证明。

## 设计代价

可变移位会形成移位选择逻辑，比较也会增加组合逻辑资源。
所有新操作目前仍在同一 EXEC 组合路径内，所以周期数不变并不意味着时钟频率不变。
必须重新运行 `make synth timing`，以当前映射和约束下的面积与关键路径评估代价。
debug/commit 输出也计入当前综合；无物理布线、时钟树和多工艺角签核。

第一批 ALU 扩展时已运行 lint、Yosys 综合和标准单元映射，结构检查为零问题。
当时 Nangate45 typical 库及默认约束下，OpenSTA 报告最小时钟周期约 19.43 ns，
仍未满足设定的 10 ns 时钟；这只是当前布局前映射的估计，不是实际芯片频率。
不能把增加 ALU 功能前后的单次映射数值波动直接解释为结构优化收益。
