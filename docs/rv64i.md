# RV64I 执行范围、终止异常与裸机 C

本节记录上一阶段的 RV64I 兼容配置（EXTENSIONS=0、HOST_TRAPS=1），其行为与回归仍保留。
**当前默认已升级为模块化 RV64IMAC、CSR、软件异常/中断和 Sv39，参见 [默认实现](modular-core.md)。**
下文的“未实现”和“宿主终止”只描述兼容配置，不适用于当前默认配置。

## 本次补齐的范围

core 和独立参考模型现已实现 RV64I 基础整数集 52 条指令的执行行为，
使用小端、64 位整数寄存器、32 位定长指令、自然对齐数据访存。
执行仍是多周期顺序状态机，没有指令重叠、缓存或分支预测。

“52 条已执行覆盖”不是正式 ISA 合规认证，也不表示已完成整台 RISC-V 机器。
当前以宿主 EEI（执行环境）接收终止异常，无 CSR、mtvec 跳转、MRET、中断或 MMU。
ECALL 固定按 M 环境报告 cause=11；没有动态特权级切换。
M/A/C/F/D、Zicsr、Zifencei 等扩展不在此范围，相关编码会被拒绝；不能运行 Linux。

## 完整指令表

| 类别 | 条数 | 指令 |
|---|---:|---|
| 上立即数 | 2 | LUI、AUIPC |
| 跳转 | 2 | JAL、JALR |
| 条件分支 | 6 | BEQ、BNE、BLT、BGE、BLTU、BGEU |
| 读取 | 7 | LB、LH、LW、LD、LBU、LHU、LWU |
| 写入 | 4 | SB、SH、SW、SD |
| 寄存器与立即数 | 9 | ADDI、SLTI、SLTIU、XORI、ORI、ANDI、SLLI、SRLI、SRAI |
| 寄存器与寄存器 | 10 | ADD、SUB、SLL、SLT、SLTU、XOR、SRL、SRA、OR、AND |
| 32 位立即数运算 | 4 | ADDIW、SLLIW、SRLIW、SRAIW |
| 32 位寄存器运算 | 5 | ADDW、SUBW、SLLW、SRLW、SRAW |
| 顺序约束 | 1 | FENCE |
| 环境调用与断点 | 2 | ECALL、EBREAK |
| 合计 | 52 | 每条均在自动回归中执行过 |

NOP、LI、MV、J、JR、RET、CALL 等是汇编器伪指令，最终展开成表中的指令；不需要另做操作码。
“全部指令”在本项目这一步特指上述基础集，不含所有可选 RISC-V 扩展。

## 访存现在怎样工作

请求新增 req_size，编码为字节数的 log2：0/1/2/3 表示 1/2/4/8 字节。
地址直接指向第一个字节，req_wdata 的最低字节对应 req_addr，依次按小端连续读写。
这不是 AXI 的对齐 beat 与 WSTRB 方案；将来接 AXI 时需另外做协议转换。
取指 size=2，恰好读取四字节，避免旧模型在内存末尾多读四字节。

例如 SB 到 0x1001 只更新一个字节，不改变 0x1000 或 0x1002；SH/SW 分别只更新 2/4 字节。
加载响应低位是实际读取的原始字节，未使用的高位填零。core 根据指令做写回扩展：

```text
原始字节 = 0x80
LB  写回 = 0xffffffffffffff80，也就是 -128
LBU 写回 = 0x0000000000000080，也就是 128

原始字 = 0x80000001
LW  写回 = 0xffffffff80000001
LWU 写回 = 0x0000000080000001
```

Load 到 x0 仍须执行访存，并可能触发访问异常。只有目标寄存器写回被丢弃。
对齐要求分别是 1/2/4/8 字节；不实现未对齐拆分，检测到后在发请求之前产生异常。
访问边界也按实际宽度检查：RAM[0xffff] 的字节读写、0xfffe 的半字访问及 0xfffc 的取指都有效。

提交记录新增 mem_size；mem_data 是按实际访问宽度截取并零扩展的原始数据，
wdata 是真正写入寄存器的最终值，因此对负数 LB/LH/LW 二者高位会不同。

## W 运算和跳转规则

W 运算只保留 32 位结果，然后总是按 bit31 符号扩展至 64 位。
即使是逻辑右移 SRLW/SRLIW，最终写回仍执行符号扩展：

```text
ADDW: 0x7fffffff + 1 → 0x80000000 → 0xffffffff80000000
SRLIW: 0x80000000 >> 0 → 0x80000000 → 0xffffffff80000000
```

W 寄存器移位量只取 rs2[4:0]；W 立即数移位量只能是 0–31，保留的 bit25 编码按非法处理。
普通 64 位移位仍使用六位移位量。

AUIPC 将符号扩展的 U 立即数加到该条指令自身的 PC。
JALR 的目标是 `(旧 rs1 + 有符号立即数) & ~1`，链接值是 PC+4。
rd=rs1 时也必须使用写回之前的旧寄存器值计算目标。最低位清零后若 bit1 仍为 1，则目标未按四字节对齐。
条件分支只有真正跳转时才检查目标对齐，不跳转的分支不应因未使用的目标而异常。

FENCE 当前可在 EXEC 完成：所有取指/数据请求都已经串行化，前一访存响应后才执行后续指令。
忽略 fm、pred/succ、rs1、rd，执行保守的全顺序约束；FENCE.TSO 编码也按更强的 FENCE 处理。
将来有 store buffer、多个请求、I/O 或多核时，必须重新设计并验证顺序保证，不能直接沿用空操作假设。
FENCE.I 属于 Zifencei，本轮未实现。

## 精确的终止异常

core 对异常设置 halted=1，保存 trap_pc、trap_cause、trap_value，由宿主结束仿真。
fault 是项目的简化分类，trap_cause 则细分具体原因：

| 情况 | fault | trap_cause | trap_value |
|---|---:|---:|---|
| 非法或未支持指令 | 1 | 2 | 指令机器码 |
| 指令目标未对齐 | 2 | 0 | 目标地址 |
| Load 未对齐 | 2 | 4 | 数据地址 |
| Store 未对齐 | 2 | 6 | 数据地址 |
| 取指访问错误 | 3 | 1 | 取指地址 |
| Load 访问错误 | 3 | 5 | 数据地址 |
| Store 访问错误 | 3 | 7 | 数据地址 |
| ECALL，固定 M 环境 | 4 | 11 | 0 |
| EBREAK | 5 | 3 | 0 |

trap_pc 始终指向引发异常的指令，包括跳转指令自己的地址。
异常指令不成功提交、不增加 instret、不写目的寄存器。
这是终止异常接口，不包含向软件异常处理程序转移或异常返回。

## 正常退出与旧版行为迁移

旧版曾将 EBREAK 当作正常结束，并计入提交。这与其异常语义不一致，现已移除。
正常程序使用 `sw/finish.inc` 的 SIM_EXIT：

```asm
lui  t4,16
addi t4,t4,-16      # t4 = 0xfff0
sd   zero,0(t4)    # 退出邮箱，0 表示成功
```

宿主只在这条完整 SD 成功提交后退出；SB/SH/SW 到同一地址不会触发退出。
此地址仍在统一 RAM 中，写入也保留在最终快照。非零状态使驱动以退出码 3 返回。
邮箱机制属于本仿真 EEI，不是 RISC-V ISA 指令。
宏占三条指令、破坏 t4，因此旧汇编示例比原来多两条提交和一次数据写入；第一条 LD 的局部波形不变。

## 已运行的裸机 C

```bash
make diff PROGRAM=c_demo
make test-rv64i
```

编译目标为 `-march=rv64i -mabi=lp64`，禁用 libc、builtins、栈保护、small-data 和链接松弛。
`sw/start.S` 设置 16 字节对齐栈，清零 BSS，调用 main，保存返回值到 0x200，然后写邮箱退出。
`sw/link.ld` 将启动代码限制在 0x200 之前，C 正文从 0x1000 起，栈预留 0xd000–0xefff。

`sw/c_demo.c` 实际执行数组循环、普通和间接函数调用、返回、栈保存、全局变量、BSS，
以及 char/short/int/long 的混合宽度操作。预期结果：

```text
transform(1..4) 求和 = 5+7+9+11 = 32
字节更新结果 = 218
半字更新结果 = 1237
无符号 32 位回绕结果 = 1
main 返回 = 32+218+1237+1 = 1488
```

-O0 和 -O2 两个版本都在三种内存时序下逐条对照通过。
没有完整 libc、动态分配、操作系统或任意扩展指令支持，不能据此承诺运行任意 C 应用。

## 回归与可复查产物

从 `make clean` 开始完整重建，运行 `make lint test synth timing`：

- 71 次基础正常/错误路径仿真，检查精确提交、性能计数和完整 RAM。
- 13 项检查器测试，包含故意损坏字段、记录顺序、停止元数据和 RAM。
- 876 组 64 位 ALU 向量 × 5 种时序配置，核对 26305 次提交及单独数学期望值。
- 126 次 RV64I 专项仿真：555 组 W 向量、58 组读取宽度/符号组合、窄写相邻字节、
  内存末端、JALR 别名/清位、分支跳转与不跳转、FENCE 保留字段、精确异常和 -O0/-O2 C。
- `build/rv64i-coverage.json` 列出 52 条所需指令和实际执行覆盖，缺一条会使测试失败。

参考模型依然是本项目代码，尚未引入 Spike/Sail 等第三方 ISS 或正式架构测试套件。
执行覆盖、定向测试和部分固定种子随机向量不等于所有输入组合的证明。

本轮 Verilator lint 无警告，Yosys 通用综合和 Nangate45 映射结构检查为零问题。
默认 10 ns 约束下的 OpenSTA 布局前最小时钟周期估计为 23.10 ns，仍未收敛到目标。
该估计包含寄存器堆和提交观察信号，没有布线寄生、时钟树和工艺多角签核，不能当作实际芯片频率。

## 当前源码组织

core 暂时仍在一个 rv64_core.sv 中，便于冻结指令语义并与原始基线比较。
文件中的译码、运算、寄存器堆和控制逻辑在综合后仍是不同硬件电路。
下一步可以利用本轮回归，拆分 decoder、ALU、regfile 和 LSU，并比较拆分前后的架构提交序列。
模块拆分本身不会自动增加并行度或提高频率。
